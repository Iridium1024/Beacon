# Beacon 0.2.0 — alpha source release

Beacon is a local multi-agent communication workspace with a Python CLI, an
optional stdio MCP adapter, and read-only browser/Desktop source components.

## Highlights

- A durable communication core separates delivery, execution, ACK, final reply,
  and waiting. Independent runtime ownership allows queued delivery to outlive
  the sending command; timeouts do not imply safe replay.
- The optional MCP adapter exposes 13 tools using the same communication core.
  Workspace and Agent identity are fixed when the server starts.
- Opt-in compact envelopes and workspace-scoped short references reduce repeated
  identity metadata while preserving the explicit boundary that Agent messages
  are not user or system instructions. Full identity remains queryable.
- Codex, Claude, Hermes, and DeepSeek Harness integrations retain their own
  session, capture, and runtime constraints. DSH supports owned runtime creation
  and exact persisted-session resume through its locked Node carrier.
- Agent guides now start from a short task menu, with separate daily-use, setup,
  compact-message, and troubleshooting documentation.
- Shared read-only session UI supports a local browser host, an optional Tauri
  host, and the optional DSH presentation adapter. Demo data is synthetic.

## Install

Extract `beacon-0.2.0-source.zip` into an empty directory. Its root is the Beacon
project itself. See [source installation](source-installation.md) for Python
3.11+ and optional runtime dependencies. Agents start at [BEACON.md](../../BEACON.md).
Install the Python `mcp` extra only when using the MCP server.

Existing workspaces require explicit operator preparation for migration and
compact messages; installing or starting MCP does not migrate a database, join
a session, or start a consumer automatically.

## Scope and limitations

- This is alpha source, not a standalone installer or bundled provider runtime.
- Automated offline, synthetic-protocol, and documentation checks cover the
  communication behavior. Authenticated live-provider/model operation and real
  workspace migration are not established by those checks.
- The UI is read-only. It does not send messages, control providers, or own
  background Gateway/Python processes.
- Compact messages are opt-in. Hermes Windows batch launchers retain the legacy
  handoff. CLI JSON output is not universally compact, and savings depend on the
  workflow and lookup frequency.
- Optional upstream runtimes require their own supported versions, credentials,
  and dependency review. Dependencies are not bundled or certified vulnerability
  free by this source release.

The source archive excludes local runtime state, private profiles, build output,
automation prompts, execution logs, and internal decision archives. The sibling
`SHA256SUMS.txt` records the release asset checksum.
