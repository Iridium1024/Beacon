# Beacon v0.1.1 (Alpha)

## 简体中文

Beacon v0.1.1 为 Codex 已登记会话增加了完整、可选的官方 app-server
激活后端。它复用 v0.1.0 已有的请求、投递、票据、响应和审计闭环，不是只做
能力探测或补充状态读取；后续可以直接替代同一功能的 CLI `exec resume`
实现。既有 `exec_resume` 仍是默认后端和明确的回滚路径。

### 主要变化

- 通过 Beacon 管理的 `codex app-server --stdio` 子进程完成初始化、会话 ID
  校验、`thread/resume`、单次 `turn/start`、最终回复捕获和有界清理。
- 直接激活、即时投递、一次性 worker、daemon worker 和本地运行配置均可选择
  `exec_resume` 或 `app_server`。
- 记录原生 thread/turn ID、状态、客户端请求、通知、服务端反向请求、审批
  决策、协议错误和响应来源。
- 繁忙 thread 不会被重复写入 turn，而会产生可重试结果；超时会尝试
  `turn/interrupt` 并清理子进程树。
- app-server 的无人值守审批默认拒绝。只有用户显式配置时才接受或在会话内
  接受审批请求。
- 新增统一 `localRuntime.codexControl` 配置块，覆盖激活后端、状态读取、会话
  补充和繁忙投递策略；既有扁平激活键继续作为兼容别名。
- 新增 `codex-session-status`。它优先读取 Beacon 自有运行时快照，也可使用
  短连接 `thread/read(includeTurns=false)` 做一次性原生状态核验，不恢复会话
  或创建 turn。
- 新增显式 `codex-session-supplement`。补充消息先进入 durable inbox，只有
  持有同一 stdio 连接的运行器可以通过 `turn/steer` 投递到匹配的 active
  turn；重复 `supplementId` 不会重复投递，歧义写入不会自动重试。
- 新增 `localRuntime.dispatchControl`。普通 `agent-dispatch-send` 默认执行一次
  有界投递（兼容 `--wait once`）；繁忙时返回稳定决策结果，不自动排队、重试
  或 steer。显式 `--queued` 保留 worker/daemon 的既有有界退避，并且不会自动
  启动 daemon。Codex 专用 busy 配置仍保持优先级与兼容性。
- 新增统一投递语义与 provider backend 契约：对外使用 `send`、`queue`、
  `supplement`、`status`，内部兼容值映射至 `inline`、`queue`、`dry_run`；
  后端选择报告 requested/effective/source/fallback，不进行静默回退。
- 新增 `ManagedProviderRuntime` 结构边界和 thread 级绑定/锁脚手架，但未实现
  常驻进程。当前 Codex app-server 仍是每次操作一个短生命周期 stdio 子进程，
  不具备 Beacon 管理的多 thread 常驻运行能力。
- 投递结果增加相互独立的 delivery/execution/reply 状态；执行完成不再被等同
  于已经产生回复，也不会自动建立反向投递。
- `agent-workspace-init` 写入项目级 `.beacon/workspace.json`，普通命令从当前
  目录向上解析最近标记；显式 profile、环境 profile 和项目标记冲突时直接
  报错，不扫描本机数据库猜测工作空间。
- 新增精简 `agent-join`：调用方只需提供可见 Agent ID、服务商和精确原生
  会话 ID，Beacon 先完成可预见冲突预检，再幂等登记 Agent、会话句柄和同名
  端点。精确查找不受最近会话展示数量限制，同一活跃原生会话不会被普通 join
  静默认领给两个可见 Agent。普通投递直接使用可见 ID；
  `agent-provider-onboard` 保留为高级兼容接口。
- 新增精简 `agent-reply`。投递不强制回复；Codex 回复写回默认
  `explicit_only`，只有显式选择 `provider_final_capture` 时才将可信最终服务商
  输出自动写成 Beacon 回复。默认 Codex 激活提示会提供正确的显式回复命令。
- 工作空间在 Provider 发现前验证；登记时发现的 `CODEX_HOME` 会贯穿状态读取、
  app-server 和 exec-resume。项目 marker 的最终写入使用并发互斥校验，避免不同
  workspace 初始化静默覆盖。
- 旧数据库可通过 `agent-workspace-init --existing-database` 显式接管并生成当前
  marker/profile；接管前验证 workspace ID，不扫描、复制或改写旧数据库。
- 终态请求关联的未投递旧队列记录对外投影为 `terminal_unprocessed`，原始事件保留
  审计但不会再被 worker 拾取。
- Windows 上的 Codex 运行时 owner PID 存活检查使用无信号 Win32 查询，不再调用
  可能终止目标进程的 `os.kill(pid, 0)`；已关闭历史连接不会探测旧 PID。
- Codex 0.146 静态兼容硬化支持从成功 `turn/completed` summary 回退最终消息、记录
  嵌套 error/deprecation 诊断，并在只读 runtime preflight 中单独探测 app-server
  stdio/schema 表面；新的 0.146 真实 Provider smoke 仍待执行。

### 边界

- 仅使用稳定的本地 stdio 协议子集；不启用 `experimentalApi`、实验性
  WebSocket、Remote Control 或 MCP。
- 不连接或接管 Codex 桌面 App 内部实例，不切换桌面任务，也不模拟 UI 输入。
- `thread/read` 使用 `includeTurns=false`，不会读取或发布完整会话历史。
- v0.1.1 仍是本地 Alpha 软件，不是公网、多用户或远程 Agent 托管服务。
- 会话补充仅完成 fake app-server 与自动化测试闭合；本版本未对真实 Codex
  Thread 执行 `turn/steer`，实机 smoke 需要后续单独授权。

详细使用方式见
[Codex registered-session activation](../providers/codex_registered_session_activation.md)。

## English

Beacon v0.1.1 adds a complete, opt-in official app-server backend for registered
Codex sessions. It reuses the existing request, dispatch, ticket, response, and
audit closed loop from v0.1.0. This is not only a capability probe or status
supplement: it can later replace the CLI `exec resume` implementation for the
same feature. `exec_resume` remains the default and explicit rollback path.

### Highlights

- A Beacon-owned `codex app-server --stdio` child performs initialization,
  thread-id validation, `thread/resume`, one `turn/start`, final-response
  capture, and bounded cleanup.
- Direct activation, immediate dispatch, one-shot workers, daemon workers, and
  local runtime profiles can select `exec_resume` or `app_server`.
- Audit captures native thread/turn ids and statuses, client requests,
  notifications, reverse server requests, approval decisions, protocol errors,
  and response provenance.
- An active thread never receives a duplicate turn; it returns a retryable
  result. Timeout attempts `turn/interrupt` and cleans up the child process tree.
- Unattended app-server approvals default to decline. Acceptance requires an
  explicit operator setting.
- A unified `localRuntime.codexControl` block configures activation, status
  reads, explicit supplement delivery, and busy-target behavior. The older
  flat activation key remains a reported compatibility alias.
- `codex-session-status` prefers a Beacon-owned runtime snapshot and can use a
  short `thread/read(includeTurns=false)` point query without resuming or
  starting a turn.
- `codex-session-supplement` writes a durable inbox item. Only the runner that
  owns the matching stdio connection may deliver it through `turn/steer` to the
  expected active turn. Stable supplement ids are idempotent; ambiguous writes
  are never automatically resent.
- `localRuntime.dispatchControl` makes ordinary `agent-dispatch-send` run one
  bounded attempt by default (compatible with `--wait once`). Busy targets
  return a stable caller decision without implicit queue, retry, or steer.
  Explicit `--queued` retains worker/daemon bounded backoff and never starts a
  daemon automatically. Codex-specific busy settings keep compatibility and
  precedence.
- A provider-neutral dispatch/backend contract now maps public `send`, `queue`,
  `supplement`, and `status` meanings to the current `inline`, `queue`, and
  `dry_run` strategies. Backend selection reports requested/effective/source/
  fallback fields and never falls back silently.
- A process-free `ManagedProviderRuntime` boundary plus thread-scoped binding
  and locking scaffold is present. No persistent process is implemented; the
  current Codex app-server path remains one short-lived stdio child per
  operation and is not a Beacon-managed multi-thread runtime.
- Delivery, provider execution, and reply state are projected independently.
  Execution completion does not imply a reply or create a reverse dispatch.
- `agent-workspace-init` writes a project `.beacon/workspace.json` marker.
  Normal commands resolve the nearest marker; conflicting explicit,
  environment, and marker profiles fail without scanning local databases.
- A short `agent-join` preflights predictable conflicts and then idempotently
  binds a visible Agent id, exact provider-native session, and same-named
  endpoint. Exact lookup is independent of recent-session display limits and
  normal join does not silently assign one active native session to two visible
  Agents. Normal sends use visible IDs;
  `agent-provider-onboard` remains an advanced compatibility path.
- A short `agent-reply` lets the receiver choose whether and what to answer.
  Codex writeback defaults to `explicit_only`; trusted provider-final output is
  written as a Beacon response only under explicit `provider_final_capture`.
  Default activation text now gives the receiver the correct explicit reply
  command.
- Workspace validation precedes provider discovery. A discovered `CODEX_HOME`
  is reused for status, app-server, and exec-resume, while concurrent marker
  initialization cannot silently overwrite a different binding.
- `agent-workspace-init --existing-database` can explicitly attach a legacy
  database and create the current marker/profile after verifying the workspace
  id, without scanning, copying, or rewriting that database.
- Undelivered legacy queue records linked to terminal requests project as
  `terminal_unprocessed`. Raw events remain auditable but workers skip them.
- On Windows, Codex runtime owner liveness uses a non-signaling Win32 process
  query instead of `os.kill(pid, 0)`, and closed historical connections do not
  probe stale PIDs.
- Codex 0.146 static compatibility hardening recovers the final message from a
  successful `turn/completed` summary, preserves nested error/deprecation
  diagnostics, and adds a read-only app-server stdio/schema surface check to
  runtime preflight. A new real-provider 0.146 smoke remains pending.

### Boundaries

- Only the stable local stdio subset is used. Beacon does not enable
  `experimentalApi`, experimental WebSocket, Remote Control, or MCP.
- Beacon does not attach to or take over a Codex desktop-owned instance, switch
  a desktop task, or simulate UI input.
- `thread/read` uses `includeTurns=false`; complete session history is neither
  read nor published.
- v0.1.1 remains local alpha software, not a public, multi-user, or remote agent
  hosting service.
- Session supplement behavior is closed by fake app-server and automated tests
  only. This release did not steer a real Codex thread; a real smoke requires
  separate user authorization.
