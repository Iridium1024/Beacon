# Config

Beacon's effective local runtime configuration is normally generated by
`agent-workspace-init` into a local-only profile. Generated profiles include:

```json
{
  "localRuntime": {
    "claudeControl": {
      "activationBackend": "cli"
    }
  }
}
```

`claudeControl.activationBackend` accepts `cli` (default/rollback) or
`agent_sdk` (opt-in). `claudeControl.replyWritebackMode` accepts
`explicit_only` or `provider_final_capture`. If omitted, CLI retains its
historical provider-final capture while Agent SDK defaults to explicit reply.
Command-line values override the nested profile; compatible flat aliases are
read only for migration and are identified in command output.

Selecting Agent SDK also requires the optional Python extra:

```powershell
py -3.11 -m pip install -e ".\python-core[claude-agent-sdk]"
```

`codexControl.activationBackend` accepts `exec_resume` (default/rollback) or
`app_server` (opt-in short-lived stable stdio app-server).
`codexControl.replyWritebackMode` accepts `explicit_only` (default) or
`provider_final_capture`. Status, supplement, and busy behavior remain under
the same control block:

```json
{
  "localRuntime": {
    "codexControl": {
      "activationBackend": "app_server",
      "statusReadMode": "beacon_snapshot",
      "supplementMode": "turn_steer",
      "replyWritebackMode": "explicit_only",
      "busyDeliveryPolicy": "queue_next_turn"
    },
    "codexAppServerApprovalDecision": "decline"
  }
}
```

Sandbox and Codex approval-policy overrides remain explicit activation or
dispatch flags (`--codex-sandbox-mode`, `--codex-approval-policy`, and repeated
`--codex-add-dir`; direct activation uses the corresponding unprefixed flags).
The app-server passes these through `thread/resume`, then verifies the returned
effective cwd, sandbox, approval policy, and writable roots before
`turn/start`. An equal or narrower result is accepted; missing or wider
evidence, including unrequested network access, fails closed.
`codexAppServerApprovalDecision` controls only reverse
approval responses and defaults to `decline`; it does not widen the resumed
sandbox or approval policy.

`hermesControl.activationBackend` accepts `cli` (default/rollback) or
`tui_gateway` (opt-in short-lived stdio gateway). Its
`replyWritebackMode` accepts `explicit_only` or `provider_final_capture`; CLI
keeps historical final capture while TUI Gateway defaults to explicit reply.
`hermesControl.gatewayPython` selects the interpreter whose installed
`hermes-agent` package is preflighted and launched. The current accepted gateway
version is exact `0.19.0`; unsupported, missing, or unknown versions fail before
ticket delivery without CLI fallback.

```json
{
  "localRuntime": {
    "hermesControl": {
      "activationBackend": "tui_gateway",
      "replyWritebackMode": "explicit_only",
      "gatewayPython": "C:/path/to/hermes-0.19.0/python.exe"
    }
  }
}
```

Equivalent explicit CLI flags are `--hermes-activation-backend`,
`--hermes-reply-writeback-mode`, and `--hermes-gateway-python`. CLI values
override the nested profile; flat aliases are migration-only and are reported
as such in `hermesControl` output.

`deepseekHarnessControl` configures the optional fourth Agent platform. It is
disabled by default and has only the `managed_runtime` backend. Unlike the
other provider controls it creates a new Beacon-owned DSH session; it never
imports an existing Web/CLI session. Windows requires the project-local Node
22.19+ carrier pinned under `integrations/deepseek-harness-node`.

```json
{
  "localRuntime": {
    "deepseekHarnessControl": {
      "enabled": false,
      "activationBackend": "managed_runtime",
      "carrier": "node",
      "executablePath": "C:/Program Files/nodejs/node.exe",
      "packageRoot": "<PROJECT_ROOT>/integrations/deepseek-harness-node",
      "cordisConfigPath": "<PROJECT_ROOT>/integrations/deepseek-harness-node/cordis.yml",
      "runtimeHome": "<APPROVED_ISOLATED_DSH_HOME>",
      "stateRoot": "<LOCAL_BEACON_RUNTIME_STATE>",
      "sessionRoot": "<LOCAL_BEACON_DSH_SESSIONS>",
      "modelProvider": "deepseek",
      "model": "deepseek-chat",
      "replyWritebackMode": "explicit_only"
    }
  }
}
```

Run `deepseek-harness-runtime-preflight` before `agent-join --provider
deepseek_harness --new-session`. Stop and recreate require explicit continuity-
loss acknowledgement. See
[`deepseek_harness_managed_runtime.md`](../docs/providers/deepseek_harness_managed_runtime.md).

The dependency range remains `claude-agent-sdk>=0.2.127,<0.3.0`. Runtime
preflight detects newer `0.2.144`-audited error/reset/origin surfaces as
optional capabilities; it neither raises the minimum to `0.2.144` nor proves a
real-provider smoke.

See
[`claude_registered_session_activation.md`](../docs/providers/claude_registered_session_activation.md)
for preflight, backend boundaries, and explicit rollback.
